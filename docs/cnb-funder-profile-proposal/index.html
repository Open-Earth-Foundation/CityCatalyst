CC-870 · Add a funder that isn't in the catalogue

Mockup of the one new path: getting a funder, its programme and its application template into the existing catalogue from a document or by hand. Every screen reuses the funding dialog, Context cards and upload rows already on develop (the CC-873 / CC-858 / CC-871 implementation of Carlos's CNB screens). The funder, programme and template tables are not changed. The result is an ordinary catalogue row that the existing selection, application context and drafting already handle.

Data

Existing columns only: no changes to funders, programmes or templates

Ingestion

The one new thing: an ingestion path into the catalogue

Pipeline

  1. Upload: existing POST /concept-notes/{runId}/uploads (OCR to Markdown, statuses, retry) reuse
  2. Extract: CA job reads the Markdown and returns a FundingOpportunityResearchBundle. The prompt is adapted from prompts/cnb/funding_opportunity_research.md: document text instead of web research, verbatim evidence, unknowns go to gaps/known_gaps. new
  3. Review: the bundle is shown in Frame 4, and edits change the bundle before saving
  4. Add: one transaction writes funders, funding_opportunities, funder_templates, funder_criteria, source_documents and funding_evidence new
  5. Select: existing PATCH /application-context reuse

Endpoints (Next.js proxy → CA)

Route
POST …/{runId}/funder-imports {uploadId}new starts extraction
GET …/{runId}/funder-imports/currentnew status + bundle when ready
POST …/{runId}/funder-imports/current/retrynew
POST …/{runId}/funders {bundle}new writes rows (upload or by-hand)
POST …/uploads, GET/PATCH …/application-context, GET …/funding-catalogueunchanged

The pending import (status, error, bundle) lives in the run's existing concept_note_context_bundles.context_bundle JSON, next to funder_context. So it survives reload with no migration.

Open decisions

Need an answer before implementation

  1. Who sees an added funder? funders has no city or owner column, so without a schema change an added funder joins the shared catalogue for every city. Is that acceptable for the pilot, or do we need scoping (which would mean one column after all)?
  2. Document with no application form. CC-858 requires every funder to have a programme and a template. If the document has no template, do we (a) let the user type the chapters (Frame 4 "Add chapter"), (b) block adding, or (c) offer a generic concept-note template?
  3. Editing an added funder later. Is it in scope for CC-870, or a follow-up? The catalogue has no edit path today.
