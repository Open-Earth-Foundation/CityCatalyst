Step 4

Saved on the run · restored after reload

Saving does two things in one request: creates the funder (scoped to the city) and sets it as the run's funder via the existing selection endpoint. The card shows provenance chips, links to the source document and an Edit profile action that re-opens step 3. On reload, the card restores from the run's application context, and an unfinished extraction reappears as a processing state on the card.

Data model

Extend cnb.funders, add one extraction job table

Principle: keep the existing funders row shape so catalogue, selection, matching prompts and the funder card keep working. Add origin/scope columns and a field-level provenance JSON for user-created funders, and a separate extraction job table so processing / failure / retry state lives outside the funder row (the funder does not exist until the user confirms).

Pydantic contracts · Climate Advisor

Draft = what the extractor returns and the review screen edits. Create = what the confirm endpoint accepts from both the form and the review screen.

class FunderProfileField(BaseModel):
    key: FieldKey
    value: str | list[str] | AwardRange | None
    provenance: Literal["entered", "extracted", "edited"]
    extracted_value: … | None = None
    evidence: FieldEvidence | None = None
    confidence: Literal["high","medium","low"] | None = None

class FunderProfileDraft(BaseModel):      # extractor output
    fields: list[FunderProfileField]
    missing: list[FieldKey]
    warnings: list[str] = []          # e.g. "several funders named"

class FunderCreateRequest(BaseModel):     # form + confirm
    model_config = ConfigDict(extra="forbid")
    fields: list[FunderProfileField]  # name required
    extraction_id: UUID | None = None # links upload + evidence
    select_for_run: bool = True

class FunderProfileExtraction(BaseModel):  # job status
    extraction_id: UUID
    status: Literal["queued","processing","ready",
                    "failed","confirmed","cancelled"]
    attempts: int
    can_retry: bool
    error_code: str | None
    draft: FunderProfileDraft | None

API

Endpoints · Next.js proxies → Climate Advisor

Everything is run-scoped so existing auth (city membership via run) applies. Only the two bold rows are conceptually new; the rest reuses the upload and selection routes already on develop.

MethodRoutePurposeNotes
POST/api/v1/concept-notes/{runId}/uploadsUpload the funder documentexisting · add purpose=funder_profile
POST/api/v1/concept-notes/{runId}/funder-extractionsStart extraction for an upload; returns extraction_id, status queuednew · 409 if upload not converted yet
GET/api/v1/concept-notes/{runId}/funder-extractions/{id}Poll status; returns draft when readynew · RTK Query polling 2 s
POST…/funder-extractions/{id}/retryRe-run failed extractionnew · 409 when attempts exhausted
DELETE…/funder-extractions/{id}Cancel / discard a pending or ready draftnew
POST/api/v1/concept-notes/{runId}/fundersCreate funder from reviewed fields (form or draft) and, by default, select it on the runnew · returns application context · 422 on validation
PATCH/api/v1/concept-notes/{runId}/funders/{funderId}Edit profile fields of a user-created fundernew · only origin != research
GET/api/v1/concept-notes/{runId}/funding-catalogueList fundersexisting · include city-scoped user funders
PUT/api/v1/concept-notes/{runId}/application-context/fundingSelect funder / opportunityexisting · unchanged
GET/api/v1/concept-notes/{runId}/application-contextRestore on reloadexisting · add pendingFunderExtraction

Extraction prompt · climate-advisor/prompts/cnb/funder_profile_extraction.md

Input: converted markdown of the upload. Output: FunderProfileDraft JSON. Rules mirror the research prompt: quote evidence verbatim, never infer award bounds, put unknowns in missing, one funder per document (warn if several are named).
